# 项目会话使用指南

项目用于保存目标和边界，会话用于分开不同讨论。项目内容不会授予任意文件路径或工具权限。

## 日常使用

1. 在「项目」保存目标与约束，审核启用。
2. 左侧「项目与会话」展开项目，点击「新建项目会话」。同一个项目可以建立多个会话。
3. 发送任务前确认底部项目标签；用「重命名」标记讨论目标。后续继续提问沿用当前会话。
4. 点击已有会话打开最新任务，历史问答可分页查看。切换会话不会取消后台任务。
5. 归档只整理列表，不删除问答或停止运行；归档后须恢复才能继续发送。「查看归档」可找回。

最近会话默认20项、最多50项；项目分组按需读取5项并加载更多。本人项目和会话不会向同企业其他成员开放，只读角色可以查看本人会话，不能管理。

## 旧库升级

全新数据库自动启用会话组织；有旧任务表但没有新会话表时，服务保留旧任务入口，隐藏新侧栏，避免启动时隐式改变历史数据。

维护窗口先停止业务写入并备份配置。源码／wheel预览：

```powershell
python -m app.harness.thread_migration --data-dir data
```

输出包括顶层运行、会话组、已有和待创建／关联的数量。预览不写库。SQLite执行：

```powershell
python -m app.harness.thread_migration --data-dir data --apply --backup backups/before-threads.sqlite
```

备份路径必须是不存在的新文件，使用SQLite备份接口，包含已提交WAL数据。迁移保留任务正文、回答、消息、旧session_id与请求哈希；子运行不加入主会话，同名会话按租户与所有者分别组织。新增表和索引，事务冲突回滚，重复执行不重复关联。

PostgreSQL先使用运维备份流程完成pg_dump，将备份保存在持久挂载目录，再将该文件路径传入 `--backup`。程序只检查文件格式与非空，不替代恢复演练。Docker个人版示例（按实际持久挂载路径调整）：

```bash
docker compose -f docker-compose.personal.yml exec app python -m app.harness.thread_migration --data-dir /app/data
docker compose -f docker-compose.personal.yml exec app python -m app.harness.thread_migration --data-dir /app/data --apply --backup /app/data/backups/before-threads.sqlite
docker compose -f docker-compose.personal.yml restart app
```

新版启动器也支持 `aegiscode --migrate-threads` / `AegisCode.exe --migrate-threads`，后面追加同样参数。0.2.5公开下载包尚未包含这些新增功能。默认EXE数据目录是 `%LOCALAPPDATA%/AegisCode`，自定义目录则显式传 `--data-dir`。

迁移后重启服务，能力接口 `threads.enabled=true` 才展示新入口。恢复时停止服务、保留故障现场副本，再由管理员恢复完整备份及配置；不要在运行中的数据库上覆盖文件。

## 接口

| 方法与路径（前缀 /api/v1） | 输入 | 输出与边界 |
|---|---|---|
| POST /threads | title、可选project_id、Idempotency-Key | 独立会话；相同幂等请求返回原ID，改内容409 |
| GET /workspace/projects | limit、before | 本人启用项目的轻量列表，不读取内容 |
| GET /threads | project_id、archived、limit、before | 按created/id稳定分页；跨范围游标404 |
| GET /threads/{id} | 会话ID | 项目名称、会话属性、最新任务ID |
| PATCH /threads/{id} | title、archived | 改名／归档恢复；禁止额外字段与宽松布尔值 |
| POST /runs | message、可选thread_id | 沿用当前会话；归档409，会话标识冲突422 |
