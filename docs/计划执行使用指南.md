# 计划执行使用指南

本指南对应持久计划执行器。0.2.10便携包、Setup与wheel均已通过逐节点执行及重启安装验收；0.2.9保持旧式冻结实现。执行内核见[集成记录](升级方案/38-持久计划执行与恢复验收.md)，产物与公开下载状态见[0.2.10验收记录](升级方案/47-0.2.10安装与公开发布验收.md)。

## 怎样使用

在工作台选择「Plan」，说明目标、允许访问的范围和需要的工具证据。例如：“读取我授权的代码文件，先整理接口，再根据读取结果说明异常处理的缺口，不修改文件。”

系统先生成最多8个顺序节点，检查前序依赖、工具范围和预算，再逐节点执行。节点可以要求非空回答，或要求指定工具的实际返回证据。前一步回答不会直接结束整个任务；所有节点通过结构契约后才生成最终交付。

选择ReAct适合边观察边决定下一步的任务。选择Reflection会在既有预算内增加证据复核，不代表自动证明答案正确。

## 在界面中核对进度

打开任务后，右侧「运行与证据」中的「计划进度」按顺序显示步骤，并标记「执行中」「验收中」「结构通过」或「阻断」。顶部「已通过 X/Y」只统计实际结构验收通过的步骤；运行失败、取消或中断不会将其余步骤自动标成通过。中断步骤显示「待核对」，需要人工核对结果。

点击步骤标题，或用键盘聚焦标题并按Enter，可展开必需工具、前序依赖、验收原因以及有界账本来源和摘要。执行记录中的计划事件仅展示有界公开证据，不转储内部模型请求、推理、系统提示或风险正文。重规划保留已完成前缀，在「归档修订」中查看旧失败后缀及原因。「历史结果复用，非重新执行」仅表示沿用匹配账本来源，不代表再次执行或新鲜观察。结构契约通过，结果正确性仍需核对。

刷新页面或重新连接会从同一任务的持久事件恢复步骤及来源，不会创建新任务或重新执行。切换任务、开始新任务、离开任务空间或退出账号时，当前计划展示会清空。没有结构计划的旧任务、以及初始规划回退ReAct的任务隐藏该区域，回退原因仍可在执行记录中查看。

本机确定性界面截图见[计划执行截图](截图/计划执行/02-工具来源-light-1440.png)，[第40号验收记录](升级方案/40-计划进度工作台验收.md)追踪独立审查结果。夹具验证展示与恢复边界，不代表商业模型质量或生产任务成功率。

## 预算与审批

默认10步是共享动作预算：规划、重规划、节点模型、风险审查模型、新工具启动、节点验收和最终汇总都会计费。等待审批、心跳和消费已保存结果不重复计费。因此最多8个节点只是结构上限，默认预算通常不能执行8个节点。

服务端为后续节点、当前必要回答与最终交付预留预算。剩余预算不足时停止操作，不先执行副作用再补验收。审批仍绑定具体调用和参数；文件修改还绑定原文件版本，版本变化拒绝覆盖。风险审查拒绝的调用不能用人工批准绕过。

需要较长计划时，由管理员在服务端`.env`设置`AEGIS_MAX_STEPS=20`并重启；合法范围为1至100，新的任务使用新预算，已有任务不重置。提高动作预算也会增加潜在模型和工具成本，不能替代费用硬配额。单轮工具请求仍最多16项，任务期限和权限边界不变。

## 失败与恢复

- 初始计划格式无效或预算不可行时，记录原因并在原剩余预算内回退ReAct。
- 节点得到已知结果但不满足契约时，最多重规划一次，保留已完成前缀及来源；后续降级仍保留尚未满足的必需工具，不能绕过证据要求。
- 用户拒批、权限撤销、取消、资料预算错误和结果未知不会触发自动重规划。
- 完整模型结果已经保存时，重启后使用原结果。未完成模型请求或已经启动但结果未知的工具进入中断状态，需要人工核对，不自动重放。
- 归档失败后缀中相同参数、相同私有范围的已知高风险成功返回，可以作为明确标注的历史来源复用；它不是重新执行或新鲜观察。只读工具可以重新观察。

刷新或重新连接只读取原任务和事件，不创建新任务。运行租约过期的旧执行器不得继续消费结果或扣费。

## 怎样判断结果可信

“结构契约通过”表示输入依赖、工具账本归属和输出形式满足检查，不表示答案语义正确。工具账本的done也不能单独证明业务成功：明确失败、非零退出码、MCP错误及未通过的协作验收都会阻断节点。

验收报告保留来源和失败原因，并明确`correctness_verified=false`与`business_success_verified=false`。涉及代码行为时仍应阅读差异、运行合适测试并核对需求。本批不提供真实供应商任务成功率或生产吞吐结论。
