# 按模型能力调整任务参数

本功能在源码和公开0.2.8安装包均提供。无需新增表或迁移；正式界面仍为TypeScript／Vite、HTML/CSS。

## 使用方式

登录后在输入区选择模型，展开「模型参数」。温度、输出上限与推理强度按该来源声明的能力开放；未开放的控件禁用并说明原因。留空沿用服务端配置，点击「恢复默认参数」清空覆盖。切换模型会清除不支持的设置并提示，仍需检查保留的数值是否超过新上限。

自动选择只展示所有候选共同支持的参数，输出上限取最小值、推理级别取交集。选择具体来源后可使用该路完整能力；它故障时仅切换到能保留全部请求参数的候选，不静默丢掉用户设置。没有兼容且可用的候选时任务明确失败。

参数随新任务保存，后续规划、工具循环及反思使用同一请求配置，模型事件保留请求参数与原有用量。它们不会修改已创建任务，也不会默认传递给子Agent或定时任务。创建失败保留输入和参数；原内容重试找回原Run，改变参数会改变请求身份。新任务和退出清空参数。

输出Token上限是协议请求参数，不等于费用硬配额。推理强度不展示内部思维链；实际可用级别、Token计量及价格以模型服务为准。

## 管理员声明能力

每路`AEGIS_MODELS_JSON`配置增加`parameters`，默认全部关闭，不根据模型名称猜测。下面只演示结构，应替换地址及模型名，并验证供应商实际支持的字段与级别后再启用；密钥值只保存在环境变量中。

```json
[
  {
    "model": "替换为已验证模型名称",
    "provider": "custom",
    "label": "工作模型",
    "base_url": "https://your-model.example/v1",
    "api_key_env": "MY_MODEL_API_KEY",
    "parameters": {
      "temperature": true,
      "output_token_parameter": "max_completion_tokens",
      "max_output_tokens": 4096,
      "reasoning_efforts": ["low", "medium", "high"]
    }
  }
]
```

`output_token_parameter`仅支持`max_tokens`或`max_completion_tokens`，未提供／null时不允许任务覆盖输出上限；声明的最大值为1至32768整数。每路协议分别映射，自动模式的共同能力不伪造统一供应商字段。推理级别最多8项、各最多32字符、不重复；当前仅面向兼容协议的`reasoning_effort`，Anthropic不能声明此字段或`max_completion_tokens`，其独立thinking协议尚未实现。

带动态推理强度且未指定温度的请求不会附带隐式温度，防止不兼容组合。任务覆盖不能被自定义正文里的同名参数反向覆盖，也不能改变消息、工具或权限。

配置声明不等于真实连通验证。管理员在服务端配置后重启，先使用小任务验证参数、工具调用、用量和备用来源；本地协议替身测试不代表商业模型联测已通过。

## API与兼容

`POST /api/v1/runs`可选`model_parameters`：

```json
{
  "message": "核对输入资料中的计算",
  "model": "从capabilities取得的route标识",
  "model_parameters": {
    "temperature": 0,
    "max_output_tokens": 512,
    "reasoning_effort": "medium"
  }
}
```

仍需Authorization及Idempotency-Key。仅允许上述三个参数；字符串／布尔冒充数值、非有限值、未知键或超过能力上限会明确拒绝。省略、null或空对象保持旧请求哈希；同一旧键改参数返回409。原Run存在时优先返回原记录，不因当前模型配置改变而重复执行。

`GET /api/v1/capabilities`的`model_routes[].parameters`公开各路能力，`model_parameters`公开自动共同能力；不会返回端点、密钥或自定义正文。API自动请求可在至少一路完整支持时使用该兼容子集，界面采用更保守的交集。旧服务缺少这些字段时隐藏参数区，原任务入口可继续使用。
