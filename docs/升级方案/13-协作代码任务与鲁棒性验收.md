# 协作代码任务、工作台与鲁棒性升级方案

日期：2026-10-02。状态：设计自检完成，新增架构待用户确认。现有修复已推送 GitHub main（aab23df）。

## 目标与方案选择

补齐子任务读取父代码工作区、依赖图和独立结果验收门，并提供可直接使用的 Fork / Worktree / Agent Team 入口。界面依据用户提供的 `C:/Users/dell/Desktop/1.png`，采用浅灰侧栏、浅色宽线程、底部输入框和按需展开的证据区。

| 方案 | 成本与优点 | 局限 | 选择 |
|---|---|---|---|
| 现有主控内核增量扩展 | 不新增服务，不扩大子写权限，沿用数据库与租约；适合个人及受控企业场景 | 每个父任务仍最多两子；不自动合并代码 | 推荐 |
| 独立工作流调度服务 | 可扩展大任务图和复杂重试 | 运维、事务和恢复成本高；首版交付慢 | 暂不采用 |
| 子 Agent 自主通信与写仓库 | 更自由的协作 | 审批、冲突和副作用边界复杂 | 暂不采用 |

## 模块与接口契约

### 工作区联动

主控先经审批调用 `project_prepare(mode=fork|worktree)`，准备管理员配置仓库的代码。子运行只允许读取该父任务目录，不获得写文件、代码执行、外部 MCP 或再次委派权限。

绑定来源由服务端通过 `parent_run_id` 解析，不接受模型指定宿主路径或任意 source_run_id。读取前检查同租户、同用户、父运行有效状态以及父子 file_read 权限，再调用现有严格 Workspace 路径检查。父目录尚未准备、非法路径、静态重解析点均明确拒绝。共享的是父工作区实时只读视图，不承诺不可变快照或抵抗不可信宿主竞态。

文件：`app/harness/service.py`、`app/harness_tools/catalog.py`、`delegation.py`；专项测试新建 `tests/test_collaboration_contract.py`。

### 任务依赖图

兼容旧 `tasks: [字符串]`，新格式使用对象：

```json
{
  "mode": "team",
  "tasks": [
    {"id": "inspect", "message": "读取 src/app.py，报告边界问题", "acceptance": {"required_tools": ["file_read"]}},
    {"id": "review", "message": "根据上游证据独立复核", "depends_on": ["inspect"]}
  ]
}
```

一批最多两个节点，总生命周期两子上限不变。整批预检拒绝空任务、重复 ID、自依赖、缺失依赖、环及超限。根节点并行入队；依赖节点仅在所有前驱通过独立验收后创建。失败前驱导致下游 `blocked`，不运行下游。上游传递有界结果摘要及原始来源引用，以不可信证据注入，不传系统权限或无限上下文。

整批创建不是原子事务，不承诺 exactly-once。创建键由父 ID、规范化参数和节点 ID 确定；崩溃后未知 started delegate 保留 interrupted，不能自动重放。预算仍预留主控汇总和父时间窗口；取消清理所有已创建的活跃子任务。

图解析与校验置于单一小模块 `app/harness_tools/collaboration.py`，调度置于 `delegation.py`，避免继续扩大 catalog。节点状态、验收证据保留在持久工具结果和任务事件中。

### 独立结果验收门

验收由内核执行，不接受子 Agent 自报“完成”作为成功依据。基础要求：真实 completed 终态、非空回答、工具账本无 started/未知结果、同用户父子链一致。显式验收契约只允许 `required_tools`，检查工具完成账本而非回答字符串；禁止通过匹配“测试通过”冒充代码正确。

返回 `verified|rejected`、原因、实际调用证据及子运行 ID。没有调用必需工具、伪造回答、失败工具、跨用户来源均拒绝；前驱拒绝不放行依赖。该门验证执行证据和契约，不证明模型结论语义正确，主控仍负责最终审查。

### 界面与 422

现有日志已定位连续三次 422 来自 `POST /api/v1/auth/register`。注册按钮为 type=button，未触发 HTML 表单校验；API 接收 Pydantic 错误数组，前端仅处理字符串，将具体原因丢弃成“请求失败 (422)”。缺少原始请求体，用户具体非法字段尚待确认。

修复方案：注册前执行表单 reportValidity；密码长度规则保持后端 8–1024；渲染字段级中文验证信息，只展示受限字段名和规则，不回显密码/令牌或完整服务器输入。非 JSON 网络错误保留可操作提示。非法输入在前端拦截，后端校验继续保留。

布局：侧栏导航与任务记录；中央任务线程、空状态和输入区；项目准备方式、协作模式作为明确控件；审查区显示子任务、依赖、验收原因与来源，审批发生时自动展开。普通阅读默认收起，保留浅/深主题、键盘操作及 390/768/1440 响应式布局。所有动态内容使用 textContent。

使用模式在服务端校验并绑定任务配置，不能仅拼接提示冒称能力。Fork 继承有界会话上下文；Team 使用独立上下文；Worktree 提供批准后仓库准备，子任务只读联动。仓库未配置时解释并禁用入口，不创建伪工作区。

## 验收顺序与负例

| 子功能 | 输入 | 输出与通过标准 |
|---|---|---|
| 注册与错误 | 空账号、7 字密码、1025 字密码、422 数组、非 JSON 错误 | 非法表单不提交；提示准确且不回显输入；合法登录注册不回归 |
| 父工作区 | 父代码、中文路径、越权用户、伪造来源、junction、.git.、ADS | 合法文本可读；越权和别名均拒绝；子不能写或递归 |
| 依赖图 | 并行双根、A→B、重复 ID、A→A、A↔B、不存在前驱 | 正常图按验收调度；非法图零子创建；失败前驱阻断 |
| 验收门 | 无证据自报成功、缺必需工具、工具失败或 started、空答案 | rejected 且列真实原因；完成工具证据满足契约才 verified |
| 取消恢复 | 父取消、超时、重复请求、创建中途失败、长答案 | 清理活跃子；报告真实终态；全文可授权读回；未知结果不重放 |
| 页面 | 新会话、任务、审批、模式选择、负例提示、小屏 | 无页面错误、无 XSS、无横向溢出、错误可定位、控件调用真实接口 |
| 发布 | wheel、便携 EXE、Setup、GitHub 下载及校验和 | 构建成功、隔离临时目录启动、readiness、安装保留数据、下载链接核实 |

确定性负例验证权限、调度和恢复鲁棒性，不代表商业模型的泛化成功率。真实模型效果另用固定任务集、模型版本、费用与失败分类评测，不借用外部论文数字。
