# 0.2.5 验收记录

## 读取性能

根因：工作台列表、详情、事件所有权检查和文件所有权检查使用完整 ORM 行，重复读取并解码内部 `messages`，其大小会随任务增长。现在公开状态使用列投影，事件和文件检查只查询带租户及用户范围的 ID；Worker 执行链仍读取完整上下文。

新增 `tests/test_run_read_projection.py`，修复前因为查询包含 `messages` 失败；修复后公开字段完全一致、分页和事件游标正确，同租户另一成员无法读取任务、事件、文件或利用游标探测任务。

2026-10-04 本机临时 SQLite，固定 2 MiB 内部上下文、各 50 次相同状态读取，交替执行完整行基线与投影读取：

| 读取方式 | 中位延迟 | P95 |
|---|---:|---:|
| 完整行 | 16.535 ms | 24.281 ms |
| 状态投影 | 9.871 ms | 18.529 ms |

该负载下中位延迟减少 40.30%。复现命令：`python -m scripts.read_performance_acceptance`。这是数据库读取微基准，不含模型调用，不代表 Redis 缓存、Token 节省或生产任务吞吐。

## 界面

旧静态资源回归确认缺少侧栏折叠按钮而失败。早期验收脚本曾因 Playwright 参数及路由回调参数错误失败，已修正脚本；不能将这些脚本错误当成功能红测。
