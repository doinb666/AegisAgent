# 启动与会话历史验收

日期：2026-10-06。当前源码在 0.2.5 基础上增量更新；不替换已公开发布资产。

## 交付内容

- 启动：实际端口预绑定，默认冲突返回可操作提示，显式 `--auto-port` 选择空闲端口；服务初始化完成后打开页面，超时与浏览器失败有手动访问提示。
- 历史：同一顶层会话按页读取公开问答，选中旧任务时不显示未来问答；只读子任务独立展示。默认每页20项，最大50项，稳定游标去重。
- 前端：安全消息组件共享，历史单独重试，过期响应不回填，保留当前答案和事件流。
- 开源展示：README场景截图、截图使用导览、使用手册和截图能力矩阵同步更新；待实施的项目线程、通知和调度有接口与验收方案。

测试命令：

```powershell
.venv/Scripts/python.exe -m pytest -q
npm.cmd run frontend:verify
.venv/Scripts/python.exe -m scripts.launcher_acceptance
.venv/Scripts/python.exe -m scripts.thread_browser_acceptance --url http://127.0.0.1:8001
.venv/Scripts/python.exe -m scripts.coding_ui_acceptance --url http://127.0.0.1:8001 --output data/acceptance/coding-current
```

两项浏览器脚本只使用服务的静态资源，所有业务API由测试夹具拦截，不写正式数据库。启动验收脚本只回收自身创建的进程，不触碰已有工作台。

## 代码整理与范围

按 code-simplifier 将历史／当前问答共用的消息渲染提取为 `createMessage`，去除重复DOM组装；启动器用一个退出事件管理等待线程，删除固定2秒定时器。首次历史加载定位当前回答，追加更早页面保留阅读位置；字段查询不读取执行 messages，沿用现有所有者隔离。

保留用户独立改动：requirements.txt、Gradio演示及Compose、用户新增文档、docs/assets/README.md删除状态，均不纳入本轮提交。

本轮未重测真实商业模型、Milvus质量、生产并发或Docker隔离；这些维度不因本轮界面回归而成为新的验收结论。未新增数据库索引，超大历史查询性能仍需后续专门评测。

## 本机展示与发布边界

本轮启动工作台在 `http://127.0.0.1:8001`，数据库就绪探针返回200，database为up。电脑展示工具无法控制当前Edge，报 `unsupported Codex auth method: apikey`；不能宣称用户屏幕已打开界面。新截图来自可复现的无头浏览器验收。

当前公开下载为0.2.5：Web和EXE都有Skills管理，EXE采用本地服务加浏览器，不是原生桌面壳。新增会话历史与启动改进尚未重新打包，不覆盖旧资产。项目／线程数据库扩展及定时任务按模式C方案评审后继续。
