# 持久计划节点与结果验收实施契约

日期：2026-10-07。承接第23号能力内核补齐，模式B：复用Worker、Run.config、租约、审批和工具账本，不新增表、不改变用户权限。以下为实施与验收要求，尚不作为功能完成声明。

## 分步交付

1. 计划契约：独立模块规范化有界顺序计划，服务端生成节点身份与可信状态；确定性核对节点输入和工具证据，先通过负例。
2. 执行接入：持久节点、模型结果用途绑定、原子验收推进、共享动作预算、一次有界重规划；原ReAct与旧运行保持兼容。
3. 产品展示：通过本人任务事件展示节点进度、验收原因和降级；后续单独进行前端与安装验收。

每步独立审查、提交；第一步纯契约见[第37号记录](37-持久计划纯契约与失败证据验收.md)。第二步运行接入已通过独立双审查及主控全量842通过、2跳过，见[第38号记录](38-持久计划执行与恢复验收.md)。专用节点界面按第39号另行验收；旧冻结安装包仍只含原规划策略。

## 计划输入

规划模型只返回`steps`，最多8项。兼容全字符串数组；结构化步骤只允许`objective`、`inputs`与`acceptance`三个字段：

```json
{
  "steps": [
    {
      "objective": "读取代码并取得工具证据",
      "inputs": {"instruction": "读取用户授权范围内的目标文件", "from_steps": []},
      "acceptance": {"output_kind": "tool_evidence", "required_tools": ["file_read"]}
    },
    {
      "objective": "根据证据说明问题",
      "inputs": {"instruction": "只引用前一步保存的结果", "from_steps": [0]},
      "acceptance": {"output_kind": "answer", "required_tools": []}
    }
  ]
}
```

`from_steps`是从0开始的前序索引，不接受布尔、自引用、前向引用或重复值。服务端转换为`n{revision}-{序号}`节点ID，模型不能提交status、账本ID、output或预算。拒绝空数组、混合类型、未知字段、非法工具清单与超限文本；原始字符串在JSON解析前限制为32768字符，dict输入另检查规范JSON长度，目标最多2000字符、指令最多4000字符，工具名最多256字符且必须属于当前工具目录。旧字符串步骤按answer、空工具清单和前一步依赖转换。

## 确定性结果门

纯回答必须非空、长度有界，前序引用均为已完成状态，当前节点没有待处理或明确失败工具。只标记`contract_satisfied=true, correctness_verified=false`，契约通过不能证明答案语义正确。

工具证据必须由服务端绑定的实际账本记录产生，同时匹配租户、所有者、Run和节点工具ID；前一步或其他运行账本不得冒充。required_tools必须全部覆盖。started、缺失记录、重复记录、错误字段、失败布尔及failed/error/rejected/cancelled/interrupted/unknown结果阻断，done不能单独作为成功证据。真实沙箱exit_code、通用returncode的非零或非法类型、MCP错误标志及未通过的协作验收也阻断。缺少明确成功信息的通用返回只能报告调用已返回、业务成功未验证。输出保存有界证据摘要与来源ID，不保存无限工具正文。

首版不执行模型提供的验收脚本，不支持任意JSONPath或宿主路径核验。纯契约模块不访问数据库、不发模型请求、不执行工具；运行层在有效租约事务里加载及绑定证据。

## 持久执行与预算

新计划结构保存在Run.config.plan，包含version、revision、replans_used、status、current_node_id、nodes和有界history；顶层Run.config.budget_policy声明共享计费口径。节点状态为pending/running/accepting/completed/blocked；节点完成、模型pending清除与下一节点选择必须原子提交。字段名属于服务端内部检查点，不将完整config暴露给状态API。

model_inflight与model_result_pending增加purpose、node_id、plan_revision和message_index。用途为plan_initial、replan、node、final、risk及初规划降级后的react；node答复只能进入节点验收，不能直接结束Run，final答复须所有节点完成。旧标记保持旧恢复语义；身份或revision不匹配直接阻断。完整结果恢复不重新请求，未完成模型或started工具仍中断，禁止自动重放。

新计划采用shared_actions_v1，默认10步：规划／重规划、执行模型、风险模型、实际新工具启动、节点确定性验收、最终汇总各扣1；已知结果恢复、复用done、审批等待及心跳不扣步。步数与调用／验收状态同事务更新；项目准备也纳入新口径。保留验收与汇总预算后才启动副作用，回退不重置计数或任务期限；原ReAct计数不变。

纯回答节点最低为模型与验收2个动作；工具证据节点最低为2加必需工具数；回答节点若声明必需工具，还需工具后的回答模型，最低为3加必需工具数。最后节点为answer时复用已验收答案，另扣1个封口动作；最后为tool_evidence时请求一次最终摘要。规划提示须显示本任务真实剩余预算，默认10动作不等于可以执行8个节点。

pending后继预留其完整最低执行成本；工具与风险阶段另预留当前answer节点的工具后答复。委派预检与实际创建子运行使用相同共享预留，防止子任务消耗父验收与封口预算，原ReAct仍只预留旧口径的1步。权限核对同时覆盖新执行和历史结果复用，读取当前用户角色与动态目录；角色或目录撤销后不得沿用旧Principal授权。

仅已知结果的契约失败可触发一次重规划，保留已完成前缀与证据，替换剩余后缀。取消、审批拒绝、越权、资料预算错误或未知结果不得重规划。初规划无效可回退剩余预算内ReAct；已进入计划后的无效重规划或二次契约失败，只能形成保留未满足必需工具的有界降级节点，不能换策略绕过验收。

同一运行、私有范围、名称与规范参数相同的已知高风险完成结果，只允许从归档失败后缀复用，活动节点或完成前缀不得借来证明新节点。复用显示来源账本ID与非新鲜观察，不创建假账本、不重复收费、不刷新原file_write审批基线；实际目录与当前权限仍核对。只读工具可以重新观察，未知started绝不重放；这不是对不同call_id的普遍恰好一次保证。

## 验收门

- [x] 新旧计划格式、空／混合／超限／状态注入／非法引用／不可用工具的负例。
- [x] 纯回答与工具证据分别验收；done+rejected、缺失证据和跨用户／节点／Run账本均失败（纯函数；运行绑定仍待接入）。
- [x] 两节点真实执行，首节点答复不能提前完成Run；节点进度与输出持久保存。
- [x] 审批跨重启保持节点与冻结参数；done复用，started未知不重放。
- [x] 模型结果检查点恢复、租约失效、取消及验收推进事务失败均不复活任务。
- [x] 共享预算包含规划、工具、风险、验收及汇总，副作用前预留，恢复与回退不重置。
