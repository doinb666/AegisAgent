# AegisCode 0.2.2：桌面工作台与全目录清理实施方案

日期：2026-10-01。承接02已实施架构与用户继续迭代、验证、GitHub提交的授权；用户本轮追加整个目录冗余代码清理。沿现有feature分支原地增量实施，不移动用户数据、不混入未关联改动。总体边界仍为受控自进化MVP，不将界面升级称为企业生产发布。

## 目标与选择

让用户能打开正式AegisCode界面，查找任务、阅读线程、审查审批与证据、预览本人任务文件、管理偏好和Skills；把无消费者旧实现剔除，使安装和维护只保留必要依赖。

| 方案 | 收益 | 成本 | 决策 |
|---|---|---|---|
| 同源桌面风格工作台 | 复用真实鉴权与任务接口，EXE无Node运行依赖 | 需整理现有脚本与状态渲染 | 本轮实施 |
| React/Tauri独立桌面壳 | 更丰富的原生菜单与多窗口 | 新增前端工具链、平台签名和安装矩阵 | 独立后续任务 |
| 全部推倒重写后端 | 可统一全新框架 | 丢失已验收恢复与权限边界，回归成本高 | 不采用 |

默认深色桌面布局，并提供浅色切换。设计场景：开发者在长时间代码任务中使用桌面显示器，任务线程与文件审查并排；白天办公可切浅色。紧凑侧栏、中央线程、可折叠审查区，输入固定在线程底部；移动端转单列。使用本地中文字体、统一SVG、OKLCH语义变量、可见焦点和减少动画支持，不加载第三方字体与脚本。

用户已要求打开界面，正式源码服务启动于127.0.0.1:8001并通过readiness，结束本轮后保留。旧8000服务不覆盖。CUA报认证不兼容，两次启动浏览器操作被自动审批拒绝，用户需点击本机入口。上述错误不伪装成浏览器已打开。

## 模块与接口契约

技术栈保持Python3.12、FastAPI、SQLAlchemy async、SQLite/PostgreSQL、HTML/CSS/JavaScript、PyInstaller；不增加在线训练或浏览器远程执行能力。

| 接口 | 输入 | 输出与约束 |
|---|---|---|
| GET /api/v1/runs | query最长200字符、status固定枚举、limit 1–100、before任务ID | 保持list响应；按created和ID倒序稳定游标；百分号和下划线按字面搜索；所有条件受tenant/owner限制 |
| GET /api/v1/workspace/overview | Bearer身份 | runs={total,by_status}、assets={total,by_kind,by_status}，只聚合本人真实数据库数据 |
| GET /api/v1/runs/{id}/files | 本人run_id | {files:[{path,bytes}],truncated}；只列任务工作区，最多200文件、1000扫描项、8层，不追随符号链接/junction，不列.git |
| GET /api/v1/runs/{id}/file?path=... | 本人run_id、最长512字符相对路径 | {path,content,bytes,truncated}；UTF-8文本预览最多64KiB，拒绝绝对/点路径/.git/链接/二进制/超大文件 |

新增查询集中在app/harness/inspection.py，通过service委派；workspace有界枚举与预览在app/harness_tools/workspace.py；HTTP鉴权和参数在harness路由。run_dict补充created时间字段，保留现有字段和默认最近100项行为。数据库schema不变。

UI读取接口不会执行工具、不自动写入或解锁审批。工作区预览属于本人只读能力；viewer仍可执行既有只读任务，但禁止修改资产、反馈、审批与成员操作。配置页展示真实已配置能力及启用指引，不回显密钥，也不把“配置存在”描述成健康探测成功。
