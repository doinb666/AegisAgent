# AegisAgent 实施任务与进度

目标：按 `02-MVP架构与验收.md` 实现持久化 Harness MVP。

架构：保留现有后端模块，新增统一身份、任务事实源、受控工具执行和自进化资产；旧无鉴权入口必须接入统一边界。

技术栈：Python 3.12、FastAPI、SQLAlchemy async、SQLite/PostgreSQL、OpenAI 兼容工具调用、MCP SDK、Docker、静态工作台、PyInstaller、pytest/httpx/ruff。

实施方式：本会话分阶段实施，按 subagent-driven-development / executing-plans 进行独立复核。用户授权覆盖计划自检后编码；用户2026-10-01已授权Git提交与GitHub更新，不强推、不发布正式Release。

## T1：身份、存储与资源边界

- [x] 身份与资源边界：`app/harness/settings.py`、`models.py`、`store.py`、`security.py`、`service.py`。
- 输入：Settings；用户名/密码；服务端 Principal；SQLite/PG URL。
- 输出：账号、哈希令牌、租户/owner 查询、版本化资产、Run/Event/ToolCall 状态。
- 验收：A01/A02/A03，令牌注销/过期、跨租户资产拒绝；测试 `tests/test_harness_store.py`。

接口契约：`Principal(user_id, tenant_id, role)`；`HarnessService(settings, model_router, tool_executor)`，其中 `tool_executor.catalog(principal)` 返回原生 tools schema；`await tool_executor.execute(name, arguments, principal, run_id)` 返回 JSON 可序列化结果。高风险判断在 service 的权限链实施，执行器再次做参数/后端边界自检。
