# Skill 文件生态与迭代计划

日期：2026-10-01。范围：在已验收的 Harness MVP 上补齐可交换、可审核的声明式技能文件，不进行模型权重训练。

## 决策

| 方案 | 收益 | 成本与边界 | 本轮选择 |
|---|---|---|---|
| 数据库声明式 Skill + SKILL.md | 复用现有隔离、版本与审批，支持文件交换 | 资源只读，不运行导入脚本 | 推荐并实现 |
| 任意本地技能目录自动执行 | 接近完整脚本生态 | 需要脚本沙箱、依赖安装及发布审核 | 暂不启用 |
| 在线 RL / LoRA | 可改变模型策略 | 需要训练算力、奖励校验与模型版本回滚 | 后续研究阶段 |

## 接口契约

- `POST /api/v1/skills/import`：JSON，`document` 为 SKILL.md 文本，`directory` 为逻辑目录，`resources` 为相对名称到文本的映射；可指定 `asset_id` 和 `expected_version` 更新已有技能。响应为资产；默认并强制 draft。
- `GET /api/v1/skills/{asset_id}/export`：返回 JSON `{document, directory, resources}`；可再次导入。无宿主任意路径输入。
- `GET /api/v1/skills/{asset_id}/resources?path=...`：本人资产资源读取，允许审核草稿；模型工具仅可读 active 技能。
- `skill_read(asset_id, path?)`：只读工具，渐进读取已启用技能正文或资源。不执行 scripts、不扩大工具权限。
- frontmatter 支持 name、description、tags、allowed-tools；不支持的字段报错。allowed-tools 必须采用内核工具名，只限制技能适用范围，不授予能力；未知工具使该技能无法被正常召回。

| 步骤 | 输入 | 输出 | 验收标准 |
|---|---|---|---|

## 安全与生产边界

SKILL.md 最多 32KiB，正文最多 16000 字符；资源最多 16 个、单项最多 16000 UTF-8 字节、总计最多 64KiB。只保存文本，拒绝 NUL。逻辑目录最多 128 字符，资源路径最多 128 字符、最多四层；禁止隐藏路径、驱动器、反斜杠和点路径。YAML 仅允许有界浅层标量/列表，禁止自定义标签和别名，使用 SafeLoader。

资产metadata规范化UTF-8 JSON最多512KiB，Skill非resources元数据最多8KiB，拒绝非有限JSON数值。客户端工具列表与来源工具合并前后均校验32项上限；旧异常Skill在召回评分前被隔离。前端导入绑定读取时的令牌与会话，切换账号后丢弃旧操作和旧响应。

创建是明确的新资产操作，当前不宣称重复创建 exactly-once；更新要求 expected_version，冲突返回409。用户审阅后启用是现有生命周期操作，不能将导入内容标记为经过测试。外部文件中的指令视为不可信知识，始终受系统权限、审批与沙箱约束。ZIP 自动解包不在本轮范围。
