# 项目会话与调度实施计划

日期：2026-10-07。用户“继续完成任务”确认第15号方案，沿推荐路径在现有功能分支实施；保护用户独立修改，不重复审批既有提交与推送授权。

目标：建立真实项目多会话、私有通知与受控调度入口，逐模块验收和交付。

架构：项目复用Asset，Thread保存会话组织，ThreadRun保持运行关联；任务内核仍负责执行、审批、幂等与租约。旧数据库需要显式追加迁移，任务和资产不删除。界面能力由服务端capabilities决定。

技术栈：Python、FastAPI、SQLAlchemy Async、SQLite／PostgreSQL、TypeScript、Vite、HTML/CSS、Playwright。

执行方式：本会话按executing-plans逐项实施，无新增子Agent。

## T1：项目会话数据与服务

文件：`app/harness/models.py`、`store.py`、`threads.py`、`service.py`，`tests/test_threads.py`。

- [ ] 先写项目多会话、同企业成员／跨租户、归档与分页测试，确认缺失接口的失败。
- [ ] Thread包含id、tenant_id、owner_id、project_asset_id、session_id、title、archived、created；新增ThreadRun以run_id唯一关联。
- [ ] 列表按created/id倒序，默认20最大50，before必须属于同一查询范围；最新run投影不读取messages。
- [ ] 创建／修改与create_run共享用户行锁；归档后不创建新运行，重试已存在的幂等请求仍返回原运行。
