# Skill轻量投影与兼容性验收

日期：2026-10-07。承接第34号模式B契约。独立规格、质量审查、主控51项专项及最终全量均通过；优化仅当前源码，未包含在0.2.9冻结安装资产中。

## 已实施

`AssetService.recall`委托到独立asset_recall模块；写入与生命周期保持原接口。第一阶段最多500项、12列轻量投影：id/kind/name/version及8个逐字段JSON投影，避免应用侧读取完整正文、整列attributes和资源体。元信息按原词法粗排32项；第二阶段按精确id/version、所有者、租户、active和类型重查最多32条正文，工具清单二次过滤和完整资产校验后精排最多8项。

保持原粗排(-score,id)、正文前3000字符、用户验证加2以及偏好／约束／画像加100规则。异常、变更候选跳过，不通过无界回填突破正文预算。Skill资源正文不注入，仅返回验证过的路径。

## 红绿与审查修复

1. 旧实现真实SQLite首条SELECT包含content与完整attributes，轻量投影断言先失败：1失败、2.78秒。新增契约整批初次12失败、12通过，驱动实现后通过。
2. 初版额外在粗排提高偏好优先级，主控审查要求保持既有顺序；恢复原粗排，并先红后绿验证候选窗口兼容。
3. SQLite json_extract把JSON布尔转成1/0，普通资产词项发生变化。先红后补布尔保真，再通过；该中间实现后来被第4项更简洁的文本提取替代。
4. 独立规格审查发现超有符号64位整数被json_extract/json_quote转换为浮点，数字词项丢失；主控扩展正负边界与科学计数，8项先4失败、4通过。改为逐字段绑定路径的SQLite `->`提取原JSON文本，PostgreSQL保留既有文本投影，41专项通过。
5. 新SQLite提取最低要求3.38.0。已初始化引擎低版本或未知版本在SELECT前返回中文503，提示升级或使用PostgreSQL；三项先失败，再补门验证。没有修改Store初始化、发布包或权限规则。
6. SQLite 3.38～3.41不支持JSON5非有限数，旧行中的NaN／Infinity可能使整次字段提取失败。8个字段改用`CASE WHEN json_valid(attributes) THEN attributes -> 绑定路径 END`，先验证严格JSON，再短路提取；不在WHERE提前过滤，因此仍保持500项窗口和12列契约。坏行投影不产生有效候选。

## 验证边界

实测Windows与SQLite3.49.1；SQLite3.38～3.41未实际运行，版本门及严格JSON保护不能替代这些运行时的专项。PostgreSQL仅方言编译与分支模拟；真实PostgreSQL、Docker和商业模型联测仍需专门环境。500项目录窗口仍存在，不宣称全库检索或任意规模索引效果；坏候选不回填可能少于8项。查询读取范围不是速度或Token收益，旧15%／40%／Redis低于50ms指标不适用于本记录。
