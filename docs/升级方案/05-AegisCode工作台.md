# AegisCode 工作台

用户于本轮追加要求：调研 Codex 前端交互并实现类似工作台，名称为 AegisCode。

## 调研状态

2026-10-01 访问 `developers.openai.com/codex/app/` 与 `features/` 的普通请求返回403；CUA 浏览器不可用，报 `unsupported Codex auth method: apikey`。已尝试官方公开Markdown、索引与站内搜索，同样403或超时，详情见01第8节。没有取得可视截图，因此首版不能宣称像素级复刻或已核验全部Codex UI功能；视觉细节采用本项目独立设计。

## 本项目界面结构

左侧导航包含新任务、任务历史、记忆、Skills、知识库与设置；中央任务线程显示用户消息、答案、工具事件与输入；右侧显示状态、审批和任务 trace。项目资料通过上传知识文档与任务工作区组织，工作区文件读取/写入由工具处理，未经审批不会写入。

任务历史可重开、SSE有游标去重和重连；审批展示工具名称与确切参数；反馈进入经验候选；记忆和Skill可创建、激活、退役、查看版本；身份与模型配置采用统一服务。设置页面只显示可用模型和后端能力，不回显密钥。

## MVP 验收

- 登录/注销、新任务、历史切换均由真实API支撑。
- AegisCode名称、统一视觉变量、三栏任务布局、中文文案；窄屏改为上下结构。
- 所有文字型不可信内容使用textContent；禁用/等待/失败/重连状态明确。
- 文档上传可检索；个人记忆跨登录加载；Skills生命周期显示来源与状态。
- 权限审批不能通过前端隐藏按钮替代后端检查。
- 已使用 Playwright + 本机 Edge 对实际页面验收登录/注销、记忆启用及重新加载、项目创建、文档上传、任务状态、审批、反馈和Skills；截图位于本目录 `截图/`。没有取得Codex官方截图，因此像素比对依然未验证。

此能力加入实施T4与验收A17。自动化任务、Git diff审阅、Worktree项目管理等若官方资料确认存在，将作为有独立输入输出和权限审查的功能实现，不用空按钮表示已完成。
