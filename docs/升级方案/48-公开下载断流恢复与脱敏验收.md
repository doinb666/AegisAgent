# 公开下载断流恢复与脱敏验收

日期：2026-10-08。承接[0.2.10安装与发布](47-0.2.10安装与公开发布验收.md)。本批改动是源码发布验证工具，未修改应用内核、前端或已冻结安装产物；0.2.10产物来源仍为7217c68，不冒称该源码ZIP包含后续脚本修订。

## 问题与输入输出

GitHub五资产上传、服务器大小和SHA256核对通过后，无凭据下载先后发生RemoteProtocolError与ConnectTimeout，原验证脚本在第一处断流退出。故障发生在读取清单前，也发生在清单一致后的产物下载前；不能把服务器摘要一致当作完整公网下载通过。

输入为本地已冻结清单、四个产物及版本号。输出为完整下载后的大小/SHA256一致记录；传输失败退出非零，完整性失败同样立即退出。脚本不读取发布凭据，也不写业务数据。

## 实施契约

- 每个清单或产物最多尝试3次，仅捕获HTTP传输异常，退避1秒、2秒；持续失败终止，不无限循环。
- 每次重新GET并从零计算大小与SHA256，使用响应上下文及时关闭断流连接。不把旧部分正文与新下载拼接，不进行未经验证的Range恢复。
- 清单同样流式读取，大小不超过本地清单；产物大小不超过冻结值。HTTP失败、超长正文、过短正文或摘要不一致不重试、不打印成功。
- 错误输出只含文件名、HTTP状态码或尝试次数；抑制原异常链，不显示重定向后的签名URL。完整性校验不因重试而放宽。
- 按code-simplifier统一清单和产物的有界流式校验，保留原版本格式、清单资产集合和本地文件验证。

## 实际验收

最初9项专项实测4 failed、5 passed：响应头断连、正文断流和持续失败没有完整重试。修复后9项通过；新增真实本机HTTP断流验证后10项通过。

独立审查发现HTTPStatusError会在回溯中显示最终签名地址。新增重定向403与传输异常含合成签名地址两项红例，实际2 failed；随后转换为安全异常并使用`from None`抑制链。HTTP拒绝仍立即失败，持续传输失败仍恰好3次。

最终主控12 passed，3.32秒；独立复审12 passed，3.39秒，Critical、Important、Minor均为0；两文件Ruff check与format --check通过。模拟传输用例显式断言退避为`[1,2]`，无需真实等待。

真实本机HTTP用ThreadingHTTPServer：首次声明完整Content-Length但只发送2字节即关闭，第二次发送完整中文正文。验证恰好两次无Authorization的GET、完整大小和SHA匹配，最后关闭本次服务器。模拟故障与真实本机传输分开记录，不替代公网下载验收。

公网验收状态与四产物的实际下载结果见第47号。脚本增加重试不能保证任意网络条件下成功；未取得完整结果时保留失败，不修改默认下载门。

## 复现

```powershell
.venv/Scripts/python.exe -m pytest tests/test_release_verification.py -q --tb=short
.venv/Scripts/python.exe -m ruff check scripts/verify_release.py tests/test_release_verification.py
.venv/Scripts/python.exe -m ruff format --check scripts/verify_release.py tests/test_release_verification.py
.venv/Scripts/python.exe scripts/verify_release.py --directory dist/releases/0.2.10 --tag v0.2.10
```

模拟错误全部使用合成地址与合成查询值，不使用实际发布签名、密钥或临时账号令牌；测试日志不上传。
