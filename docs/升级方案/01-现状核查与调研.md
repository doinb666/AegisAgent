安全补充：上传路径使用原始文件名，无大小限制；只读 SQL 的关键词过滤不能作为权限隔离；长期记忆过滤使用双引号但只转义单引号；语义缓存索引更新不是事务操作；Redis 摘要删后重写有并发丢消息风险。新入口必须关闭这些未经隔离的路径。

## 2. 可使用的原项目介绍

基于 FastAPI 与 Python 异步接口实现 AI Agent / RAG 后端原型，包含 ReAct、Plan-and-Execute、反思评分、Milvus 向量检索、内存 BM25、RRF 融合、Cross-Encoder 重排、Redis 短期记忆及摘要压缩、模型路由和三态熔断组件，支持 PDF/文本规则分块、Docker Compose 与 Gradio 演示。当前 API 主要接入模型聊天与文档入库，完整 Agent/RAG/记忆闭环及量化效果仍需集成验收。

用户要求的是升级实现与方案，而非导出简历文件；本文只对齐项目描述，不编造指标。

## 4. 从用户提供的文章提取工程思想

1. 推理时进化：成功轨迹提炼程序性步骤；失败轨迹拆解缺失能力、适用边界和错误恢复，不直接复制失败行为。
2. Skill 生命周期：候选、评测、激活、修订、退役；保留版本、证据、作用域、失败计数与回滚记录。只增不减的库会污染召回。
3. 记忆策略本身可评测：存什么、何时存、检索多少、何时遗忘分别作为参数/策略候选；不可自动修改安全规则。
4. 工具发现与工具启用分离：自动发现只产生候选，受控环境验证后由有权限的人启用。
5. 多 Agent 共享经验先去标识化，企业共享需要明确发布；用户偏好不得自动成为租户通用规则。
6. 防止 Misevolution：外部资料不变成系统指令、失败不等于新知识、模型自评分不等于测试通过、资产不扩大权限、训练/评测数据隔离、灰度和回滚。
7. 在线 RL 是另一条部署路径：需要自有可训练模型、算力、奖励数据与离线安全评测；调用商业 API 并不能更新其模型权重。MVP 不声称具备在线 RL。

## 9. 知识检索配置与验收边界

`KnowledgeService(settings, service)` 的异步契约为 `index(principal, document, chunks)` 与 `search(principal, query)`。分块保存到既有 document 资产元数据，数据库承担持久化；进程重启无需依赖内存索引恢复。默认 BM25 按证据块计算，支持英文词与中文双字切分。查询在数据库 WHERE 中同时限制 tenant_id、owner_id、document 类型与 active 状态；正文发生版本变化时，不使用旧版本分块，按当前正文重建有限词法分块。

`search` 返回 `results / backend / warnings / truncated`；每项证据包含分块 ID、document_id、文档版本、来源名称、chunk_index、内容与实际检索分数。默认最多检查 64 份本人文档、2048 个分块、200 万字符，返回 5 块；文档按名称与 ID 排序，因此达到预算时不保证覆盖后面的文档。`truncated=true` 和 warnings 明确说明范围限制。`index` 返回 document_id、实际存储块数与同样的截断/警告信息，不虚构召回率或延迟。

配置通过 `AEGIS_` 环境变量加载：

| 配置 | 默认 / 作用 |
|---|---|
| AEGIS_KNOWLEDGE_BACKEND | bm25；设为 hybrid 才开启可选向量分支 |
| AEGIS_KNOWLEDGE_EMBEDDING_MODEL / AEGIS_KNOWLEDGE_EMBEDDING_DEVICE | 空；显式配置 sentence-transformers 模型路径或模型名、设备，懒加载 |
| AEGIS_KNOWLEDGE_MILVUS_HOST / PORT | 空 / 19530；显式配置外部向量服务 |
| AEGIS_KNOWLEDGE_MILVUS_USER / PASSWORD | 空；密码使用 SecretStr，不将外部原始异常回传 |
| AEGIS_KNOWLEDGE_MILVUS_COLLECTION | aegis_knowledge；参与用户独立集合命名，实际集合使用租户与用户哈希 |
| AEGIS_KNOWLEDGE_RERANK_MODEL | 空；显式配置 CrossEncoder 模型，本地懒加载 |
| AEGIS_KNOWLEDGE_TOP_K | 5，范围 1–20 |
| AEGIS_KNOWLEDGE_MAX_DOCUMENTS / MAX_CHUNKS / MAX_CHARS | 64 / 2048 / 2000000，索引与查询预算 |
| AEGIS_KNOWLEDGE_TIMEOUT_SECONDS | 10；每个可选外部分支的等待上限 |

现有 MilvusManager.search 没有 expr 过滤契约，因此采用按 tenant＋user 隔离的物理集合，并把向量命中 ID 再关联到当前查询范围、active 状态和当前资产版本的权威证据块。不会访问未隔离的旧全局集合。混合检索通过 RRF 融合排名，可选 CrossEncoder 重排；配置缺失、连接/模型失败或超时时保留 BM25，并返回不含凭据的降级原因。取消等待不能强制终止已经启动的第三方同步 SDK 线程，真实部署仍需服务端超时配置。

本地回归覆盖重启恢复、双重隔离、外部 ID 误返回防泄露、旧版本/退役排除、预算截断、缺配置与外部分支失败/超时回退。真实 Milvus、embedding/CrossEncoder 下载与推理、模型维度兼容性、远程认证和检索质量基准均未验证；测试中的替身不等于外部服务验收。按用户独立集合的运维成本也需要真实规模评估。
