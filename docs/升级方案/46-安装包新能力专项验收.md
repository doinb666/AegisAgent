## 脚本职责与边界

`scripts/package_harness_fixture.py` 只绑定 `127.0.0.1` 临时端口，不导入 `app`，不替换应用服务对象，返回确定性文本或 calculator 原生工具协议。最多 48 次请求、每请求 256000 字节、64 条消息、32 个工具目录项，连接读取超时 5 秒，最多 4 个并发连接；SSE 帧最多 4096 字节、每响应最多 128 帧。未知任务、非法模型名、错误工具证据、无唯一来源的修订输入均拒绝。修订输出只含资产 ID 和文本建议，不生成权限、启用状态、版本或外部工具调用。

`scripts/package_harness_acceptance.py` 可选 `--source`、`--portable`、`--setup`、`--wheel`，只允许一项。默认自有随机本机端口，拒绝 8001/8002/8003；使用独立中文临时 cwd 和数据库，清除继承的模型配置及 `PYTHONPATH/PYTHONHOME`。源码模式唯一例外是显式设置源码 `PYTHONPATH`，输出明确标注“源码研发验证”；它不能替代安装包绿测。wheel 创建独立 venv、安装实际产物及依赖，验证实际 `app.__file__` 位于该 venv。Setup 与便携只运行产物自己的启动器。

便携解压检查路径归属，但只支持受信任的项目发布 ZIP；没有实现任意 ZIP 导入的数量、压缩比例和总大小防护。临时目录由本次上下文管理器回收，进程只按本次启动 PID 回收，不按端口终止现有服务。独立提取的旧包静态文件保留于系统临时目录，未递归清理其他目录。

`scripts/package_acceptance.py` 仅增加可选 `--harness` 参数；原默认验收及 `--features` 顺序和原协议夹具保持原行为。新专项复用原脚本的生产启动检查、静态 SHA 校验、有界事件读取和进程管理。

## 闭环断言

1. 通过实际产物 HTTP 注册两个独立账号并登录。
2. Plan 请求建立两个顺序节点，第一节点要求 calculator 账本证据，第二节点依赖第一节点输出；核验两条节点验收事件，保留“结构契约满足、正确性和业务成功未验证”边界。
3. 普通任务真实调用 calculator，账本 `done`，参数为 `2+3`、实际结果为字符串 `5.0`；后台经验提炼生成带 `source_run_id`、工具来源和 `extracted` 标记的唯一 Skill 草稿。
4. 来源草稿不召回；经 HTTP 人工启用后，新任务 `assets_recalled` 事件包含来源 ID、版本和原始 Run。
5. 新任务提交失败反馈，后台生成版本 1、状态 `draft` 的未验证修订建议，保留原 Skill ID、版本、来源 Run；`repair_verified/manual_verified/user_verified` 均为 false。原 Skill 完整内容、状态、版本及历史快照保持不变。
6. 再次新任务召回原 Skill，不召回修订草稿；重复反馈后观察 2.5 秒，覆盖后台 2 秒空闲轮询，模型请求及修订草稿不增加。
7. 另一账号 GET Run、事件、原 Skill、修订 Skill、原 Skill 历史均返回 403/404。
8. 停机后只读实际 SQLite，核验两条 calculator `done` 账本、Plan 节点终态、节点绑定的真实账本主键、账本来源；工具账本以 `SELECT *` 完整行保留全部列名和值，含主键、租户、所有者、参数哈希及将来新增列；所有演化状态为 done/skipped，修订状态非 queued/started。重启后 HTTP Run、事件、资产与历史和只读完整工具账本相同，观察 2.5 秒后模型请求不新增。
9. 首页 HTML 包含 `plan-progress` 与 `feedback-note`，实际服务 `app.js` SHA 与传入构建静态文件一致。

不直接改 Run、Asset 或数据库产生证据。风险分类在确定性专项中关闭，演化开启；未执行外部工具。安装新能力“通过”仅能由真实新产物产生。
