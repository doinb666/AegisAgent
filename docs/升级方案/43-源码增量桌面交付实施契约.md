# 源码增量桌面交付实施契约

日期：2026-10-07。沿用已授权的多方式安装与发布任务。本文为后续交付契约，不能作为新安装包已发布的证据。

## 目标与冻结边界

在Skill反馈修订完成独立规格、质量审查及源码回归后，用新的版本号构建Windows安装器、便携ZIP、wheel与源码ZIP，让桌面入口包含最新TypeScript工作台、持久计划和修订草稿机制。保留0.2.9及所有旧资产；用户未提交的Gradio、依赖与独立文档不进入冻结快照。

继续使用现有`scripts/prepare_release.py`从已提交Git快照构建，不能从脏工作区直接复制生产代码。新版本号在正式构建前核对未占用，提交`pyproject.toml`、`package.json`和锁文件后冻结来源SHA。未完成独立安装与公开下载核对前，README继续推荐已验证的0.2.9。

## 输入输出与文件职责

| 文件或模块 | 输入 | 输出 |
|---|---|---|
| 版本配置 | 双审查通过且已提交源码 | 一致的新版本号、冻结提交 |
| `scripts/package_model_fixture.py` | 原增量输出与文件审批SDK请求 | 保持0.2.9原有夹具、自检及`--features`行为 |
| 新增Harness安装专项模块 | 独立本机SDK协议替身、生产启动器及真实安装产物 | 两节点计划、来源Skill、人工启用、失败修订、跨账号拒绝与重启证据；原增量／文件夹具保持兼容 |
| 安装验收模块 | 独立中文目录、冻结安装产物、随机本机端口 | 安装、实际HTTP执行与重启记录；不连接业务数据库 |
| `scripts/prepare_release.py` | 冻结Git快照 | 五个新发布资产，SHA256清单 |
| 发布和下载验证脚本 | 已验收五资产及发布说明 | GitHub新Release；无凭据下载大小和摘要匹配 |
| README与安装指南 | 已验证的发布链接 | 下载入口、安装步骤、迁移及实际能力边界 |

若需扩展安装脚本，采用独立可选参数，保持0.2.9原有安装、增量和文件差异验收契约。模型夹具中的技能修订调用仅生成文本，不自动调用外部工具。

脚本实施采用独立`package_harness_fixture.py`和`package_harness_acceptance.py`，原安装入口只追加可选`--harness`。源码模式仅用于研发验证，不充当独立Setup或wheel安装绿测；旧包红例使用旧包真实静态资源，不能因新旧app.js摘要差异提前失败。新版安装门仍需提交冻结后的真实产物。

## 分步验收门

- [x] **源码门。** Skill修订后台及前端均双审查通过，主控冻结回归退出0；后台全量902通过、2平台跳过，前端四模块浏览器集成退出0，详见第42、45号，不与旧批次相加。
- [x] **脚本红例。** 新增安装专项对旧0.2.9便携包、Setup和独立wheel实际安装启动后失败，均明确缺少持久结构化Plan事件；使用各自旧静态摘要核对，未以版本字符串或新旧资源差异代替功能红例，见第46号。
- [ ] **执行闭环。** 从安装产物注册独立账号，经工具证据生成并人工启用来源技能，新任务由真实召回事件记录版本；失败反馈产生未验证修订草稿。核对原技能不变、草稿不自动召回、重复反馈不产生新草稿。
- [ ] **计划闭环。** 经本机SDK模型创建多节点计划，节点证据与终态保存；首页提供计划区域，刷新或重启保持同Run，模型请求数和工具账本不增加。
- [ ] **隔离及预算。** 新账号不能读旧账号草稿或任务；非法模型输出、不存在来源与权限变化不污染资产。夹具提高预算时明确记录，与生产默认10动作区别。
- [ ] **构建门。** 前端类型及构建退出0，wheel静态资源与源码一致；新目录五资产齐全，不覆盖旧版本。
- [ ] **独立安装门。** Setup与wheel分别安装到新中文目录；wheel检查导入实际来自独立venv，不能被本地源码遮蔽。临时目录连接显式关闭，只回收本次进程树。
- [ ] **审查门。** 新安装专项脚本已先规格再质量独立复审通过，主控32项边界测试及源码生产启动器闭环通过，见第46号；冻结新产物的重复验证仍待完成。
- [ ] **公开发布门。** 新Release大小与服务器摘要匹配；无Authorization下载全部资产并核对SHA256后，才更新README默认下载版本。

## 限制

EXE仍采用本机FastAPI服务与浏览器工作台，不能称为原生WebView。安装专项验证Windows、SQLite、HTTP和本机协议替身，不替代真实供应商、Docker、PostgreSQL或生产吞吐。Skill修订草稿不代表修复有效；独立重验与活动版本替换仍由另一期契约完成。
