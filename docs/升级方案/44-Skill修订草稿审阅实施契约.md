# Skill修订草稿审阅实施契约

日期：2026-10-07。承接第41号后台修订与既有技能库，不新增API或执行权限。后台双审查与主控验收通过后实施；本文不是界面已完成的声明。

## 用户目标与设计

用户在明亮办公环境中审阅同名技能时，应直接分辨原活动版本与失败反馈产生的新草稿。沿用TypeScript、Vite、原生HTML/CSS及现有语义色，以短来源行、未验证说明和按需展开的文本对照呈现，不增加新页面或装饰指标。深色与窄屏保持同一交互。

现有“技能库”条目继续保留正文、来源任务、版本记录、启用及退役操作。只有元数据符合服务端修订来源契约的条目新增“修订草稿”来源行和“对照原技能”；普通、导入及历史技能保持既有行为。

任务审查区在反馈按钮前增加可选文字说明，使用既有反馈API的`note`字段；长度按服务端4000个Unicode码点校验。失败反馈可说明遗漏、约束和期望，成功反馈也可记录验收依据。保存失败保留说明，成功后清空；切任务、退出或换账号同步清空，不让上一任务说明误发到下一任务。同一任务重新读取、离开视图再返回仍保留未提交说明，不把页面读取当作反馈成功。

## 组件与输入输出

| 文件 | 职责 |
|---|---|
| `frontend/src/skill-revision-review.ts`（新增） | 验证有界来源字段、纯文本提示、按需读取原技能、对照状态与过期响应保护 |
| `frontend/src/app.ts` | 技能条目接入独立组件，传入同源API与视图有效性函数 |
| `app/web/index.html` | 现有任务审查区的可选反馈说明、可见标签和就近提示 |
| `frontend/src/workspace-ui.ts` | 修订事件使用明确中文标题及短说明，不把草稿完成称为修复成功 |
| `app/web/styles.css` | 原文／建议对照、浅绿及警示状态，复用现有变量 |
| 构建产物与浏览器验收 | 静态一致性、实际HTTP交互、困难负例与截图 |
| 指南和截图导览 | 审阅步骤、版本变化、启用并不等于独立测试通过 |

输入为本人资产公开元数据中的原技能ID、原版本、来源任务及`repair_verified=false`。对照只调用既有`GET /assets/{id}`，不额外读取任务配置，不提供任意URL。输出为原技能与未验证建议的有界纯文本；来源、版本与状态均有中文标签。

## 交互状态与验收

- [x] **红例。** 真实HTTP生成修订草稿后，原界面缺少明确“修订草稿”、原版本及对照入口；普通草稿不得误标修订。
- [x] **默认与加载。** 显示“基于原技能vN，未验证建议”；展开时才请求原技能，重复展开不无限请求；加载状态保留原草稿正文。
- [x] **成功与版本变化。** 原版本仍匹配时展示对照；当前版本已改变、退役或原来源不匹配时明确提示“原技能已变化”，不假装当前正文就是生成时原文，也不自动启用或覆盖。
- [x] **失败与重试。** 404／403仅提示无法读取或已无权限，不泄露其它资产；网络失败提供手动重试，保留输入及正文；未知状态不给错误成功提示。
- [x] **反馈说明。** 可选说明按原API长度校验；空说明兼容原按钮，成功/失败反馈绑定选中Run，网络失败保留文本；同Run重新读取或切视图返回保留，切任务和换账号清空，禁止直接解释不可信HTML。
- [x] **边界与隔离。** 元数据缺失、类型错误、巨值、HTML及恶意正文仅安全文本或不启用入口。切视图、筛选、刷新列表或换账号后，旧请求不得回填新条目。
- [x] **审阅安全。** 不自动提交审批或启用，不将用户反馈当修复验收；对照在有限长度内提示截断，可通过既有本人资产正文入口核对。保持原工具依赖与服务端权限判断。
- [x] **视觉及键盘。** 深浅390／768／1440、44px操作区、可见焦点及减少动画验收。原生details更新保留展开与焦点，不靠颜色单独说明风险。
- [x] **实测与双审查。** 构建和类型退出0，真实HTTP与模拟网络负例分别标注；原资产浏览器回归通过。实际code-simplifier清理，先规格后质量，主控冻结复验。
- [ ] **交付。** 指南、README价值说明和截图随中文提交同步GitHub；发布范围以新包独立安装证据为准，不覆盖0.2.9。
