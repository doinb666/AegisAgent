# Codex 截图功能对齐与下一阶段方案

日期：2026-10-06。依据用户重新提供的 `1.png`、当前源码及 0.2.5 交付记录。状态区分当前源码、已发布安装包与待实施方案，不承诺复制未公开的 Codex 内部机制。

## 范围与策略

采用 TypeScript + Vite、HTML/CSS、FastAPI 和现有持久任务内核。保留主控规划、工具审批、只读子任务和用户隔离；让记忆、技能生命周期和执行证据成为 AegisCode 的特色。截图可核对可见交互，无法定义 Codex 的全部能力。

| 方案 | 优点 | 成本与边界 |
|---|---|---|
| 推荐：先补齐 Web 产品闭环，沿用 EXE 本地服务 | 单套界面、现有安装方式、按能力验收，维护成本最低 | 原生菜单、托盘和桌面更新暂缺 |
| 同时引入 Tauri 桌面壳 | 原生窗口、体积较小，可包装已有静态工作台 | 新增 Rust、Python 服务生命周期与打包签名；成本中等 |
| Electron 全桌面产品 | Node 生态丰富、跨平台桌面能力成熟 | 安装体积与资源占用增加；桥接权限和自动更新成本较高 |

先实施推荐方案；原生壳单独评审，不把现在的 EXE 宣称为 WebView 应用。

## 本轮可直接交付的模块

按用户工作流模式 B，沿用现有存储和权限，不迁移数据库。

1. 启动器：输入 host、port、auto-port；输出实际绑定地址。默认冲突明确失败，显式选择自动端口时才切换；服务初始化完成后打开浏览器。验收端口竞争、错误地址、IPv6、失败启动、超时与浏览器失败。
2. 会话问答：`GET /api/v1/runs/{run_id}/thread?limit=20&before=...`。输入本人选中的运行与分页游标；输出公开问答、是否还有历史和下一游标。最大50项，按 `(created,id)` 稳定分页，只展示不晚于选中运行的顶层会话，子任务仅展示自己。每次查询检查租户及所有者，游标必须属于相同会话和可用时间范围；不读内部 messages。
3. 展示：历史内容使用安全消息组件；可重试、去重、切换任务／账号丢弃过期响应；保留当前答案与事件流。截图验收分页、顺序、注入负例、异步竞争和窄屏。

## 下一阶段架构，待确认后实施

以下涉及数据库新增表与后台调度，按用户模式 C 先确认方案。代码生成前完成接口、隔离和迁移评审。

### P1：项目与线程组织

- 数据：继续复用 `Asset(kind=project)` 保存项目目标，不建立第二套项目资产。新增 Thread（id、tenant、owner、project_asset_id、标题、归档、created）和 ThreadRun 关联（run_id 唯一、thread_id、tenant、owner）。所有关联必须同租户同所有者。
- 接口：创建／列出／重命名／归档线程；列表支持项目筛选和游标分页。创建任务可选 thread_id，服务端验证归属并使用 thread.id 作为会话 ID。旧 session_id 请求继续兼容。
- 输入：已审核项目资产和用户任务；输出：左侧项目分组线程、当前项目标签、连续问答。项目资产不是宿主任意目录路径授权。
- 迁移：新增表及必要复合索引，通过显式迁移命令运行并先备份。历史 session 生成可追溯的兼容线程，同步前 dry-run；不覆盖任务和资产，校验条数与所有权。
- 验收：同项目可开多线程；不同线程上下文不串；同企业不同成员不可读；重复迁移结果稳定；归档不删除问答；空项目、大列表和同时间游标有序。

### P2：通知与定时任务

- 通知：站内通知表记录 owner、event_id 唯一、run_id、类型、已读时间。任务终态及等待审批通过事务事件生成通知，可分页和标记已读。无邮件／消息外发。
- 调度：Schedule 与 Occurrence 表记录用户、UTC触发时间、任务模板、状态、租约与触发结果。唯一键 `(schedule_id, scheduled_at)`，创建任务使用确定幂等键；多个 Worker 以数据库租约领取，心跳和失效回收沿用现有范式。
- 安全：自动任务仅使用现有只读工具子集，不扩大权限；需要写文件、MCP、代码执行等能力的计划暂不支持。用户仍需登录管理自己的计划。
- 时间策略：首期一次性和固定间隔，不支持 cron。界面输入带时区时间，存储 UTC；重叠触发跳过并记事件；停机错过只补最近一次，避免恢复时任务洪峰；不确定工具副作用不重放。
- 验收：双实例争抢同一时刻只创建一个运行；暂停／归档不会新触发；取消后不恢复；用户隔离、极端间隔、时区转换、租约失效和配额降级有负例。

### P3：模板、MCP 导览与附件

- 模板只预填任务，不自动执行；每个示例展示所需工具、输入与可验证输出。
- MCP 导览展示配置的工具名和状态，不接受任意宿主命令或网页指定服务器自动安装；实际调用继续白名单、参数 Schema 和审批。
- 附件复用知识库解析与私有资产，输入区引用资产 ID。不存在、未完成解析和跨用户附件明确拒绝；上传重试不得重复触发任务。
- 验收：无配置时有可操作说明；文件超限、扫描 PDF、恶意资源内容与跨用户引用不得伪装成功。

### P4：差异审阅与模型体验

- 差异：以本人工作区文件读取为基础，有界展示前后文本；保存仍走精确工具审批。基线内容 hash 变化时拒绝覆盖，绝不增加任意路径写入接口。
- 推理强度：先建立 provider 能力表，UI 只展示已验证组合，参数预算和用量记入 Trace。
- 模型流：逐 Token 事件与持久任务事件分开，重连不能再次创建任务或重放工具；不支持流的来源完整回答降级。
- 验收：修改竞争、越界文件、极大差异、断线重连、协议参数不兼容与模型切换；不借用历史无证据性能指标。

## 生产化约束

数据库范围检查、幂等、租约、工具账本、SSE断点读取和有限熔断保持在内核；计划和线程只建立在其上。新增索引需验证 SQLite／PostgreSQL 查询计划；界面采用有界分页，避免一次加载全历史。共享限流、集群容灾、在线 RL 和可写子 Agent 不属于本阶段完成项。

自进化继续采用“执行证据—反馈—候选提炼—审核—索引—复用—修订／退役”，不自行升级权限或更改安全规则。效果需要独立任务集、负例和可复核评测，不能把工程参数当收益。
