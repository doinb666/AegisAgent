日期：2026-10-07。对应[第41号契约](41-Skill反馈驱动修订实施契约.md)。本批为源码增量，0.2.9安装包不包含此能力。修订草稿未经过修复效果重验，不自动替换原活动技能。

## 本批行为

本人completed或failed任务收到失败反馈后，从服务端保存的召回版本中选择最多2项有来源的活动Skill，登记私有后台修订。模型仅生成低信任文本建议，严格校验JSON、长度和对象ID；新草稿保留原工具、资源及边界，原技能保持活动、内容和版本不变。草稿、版本快照和结果事件同事务保存。

相同反馈指纹包括已完成和在途A→B→A均不重复消耗模型或生成草稿。已被其它反馈替代的在途A再次提交时明确跳过，旧输出不可保存；未被替代的当前请求仍可在过期租约后恢复纯生成。角色降级、来源变化、反馈漂移和旧租约均在封口检查，不能重放原工具。

## 关键负例与修复

| 场景 | 核对范围 |
|---|---|
| 实际使用路径 | 真实工具执行沉淀、用户成功反馈启用、新任务未经改写的召回事件、失败反馈生成私有草稿 |
| 来源门 | 无来源、异用户／异租户、同企业其他用户、非Skill、退役、原版本变更、来源任务归属改变均不能修订 |
| 有界版本 | 巨值`10**100`原先触发SQL整数溢出；限制为正SQL Integer范围后跳过畸形引用，正常反馈仍保存 |
| 已完成ABA | 两种反馈各处理一次，再提交第一种不新增模型成本或草稿 |
| 在途ABA | 独立规格原例calls2／drafts1；领取指纹持久化后calls1／drafts0／skipped，旧作业输出丢弃 |
| 恢复与并发 | 双Store单领取、过期租约恢复、旧作业和新失败反馈隔离、原提炼与修订命名空间均保留 |
| 事务门 | 草稿、快照及事件写入任一失败整体回滚 |
| 模型及权限 | 重复JSON键、额外字段、未知对象、超长、空回复、注入、降权和反馈漂移不扩大权限 |
| 共享容量 | 前台模型与后台修订共用现有进程容量门；不据此宣称集群限流完成 |
| 已完成计划 | 反馈、经验和修订事件不再把已完成计划重新标为blocked；原pending清理保留 |
