# 模型参数能力契约实施计划

承接第15号已确认P4方案。当前只补任务级参数及兼容兜底；真正模型增量流与差异审阅分别验收，不将持久SSE事件称为逐Token输出。沿用现有Python／FastAPI、TypeScript／Vite，不新增依赖和表。

## 输入、输出与模块边界

管理员在每路模型配置声明可开放的任务参数：是否允许温度、输出Token上限及对应协议字段、支持的推理强度。默认不开放任务级覆盖，不依据模型名称猜测能力。声明只代表管理员确认的配置，真实服务仍需连接验证。

API任务可选`model_parameters`，仅允许温度、输出Token上限、推理强度。严格校验类型、范围及所选路由能力；拒绝布尔冒充数字、非有限值、未知键、未支持组合。空参数保持旧幂等哈希，非空参数写入Run配置并参与哈希。重试先找回原任务，不能因当前能力变化而重复执行。

模型路由将统一参数映射到各自声明的协议字段；带参数的请求仅使用兼容候选，故障降级不静默丢掉用户约束。不兼容候选跳过且不影响熔断；选定路由不存在或能力不足在创建前明确拒绝。自动选择的界面仅提供所有候选共同支持的参数。

主任务、规划与反思调用遵循其任务参数，并在持久模型事件保留请求参数及原有用量。不默认把父任务参数传给子任务或定时任务，不允许参数覆盖消息、工具、流式协议、密钥或URL。

前端独立参数模块接入公开能力；按模型切换展示可用控件、范围与不支持原因。修改参数改变请求身份；失败保留输入和参数，新任务／退出重置，旧服务缺能力时隐藏。参数控件仅影响新任务，不修改已创建任务。

## 验收门

1. 配置解析与公开目录不泄露端点、密钥及自定义正文；错误不回显原始配置。
2. 真HTTP／SQLite验证严格输入、旧hash兼容、同键参数冲突、原任务恢复及私有范围。
3. 协议连接替身检查发送参数、不同字段映射、兼容候选兜底、不兼容不发送、超时与取消释放并发槽。
4. 真实浏览器验证模型切换、缺能力、参数重置、提交失败保留、旧服务兼容、窄屏和安全文本。
5. 规格及质量审查后运行适当回归，更新使用说明、截图与需求矩阵，分模块提交推送。

## 边界

Token上限是模型请求参数，不等于费用硬配额。推理强度不是展示内部思维链。不同厂商参数差异必须显式声明；商业模型真实效果、首Token延迟和成本收益未经联测不写成已验证数字。
