# 计划执行进度工作台实施契约

> 执行方式：沿用 subagent-driven-development，实施后先规格审查，再质量审查。本阶段承接已授权第36号契约的产品展示，不新增权限、任务创建接口或数据库表。

日期：2026-10-07。

**目标：** 用户能在现有 TypeScript 工作台查看真实计划节点状态、验收原因、历史重规划及证据来源，刷新或重连沿用同一任务。

**架构：** 独立计划展示模块消费本人持久事件，维护最多8节点的展示状态。原 Run API 不返回内部 config；展示不执行工具、不提交审批，也不把结构验收解释为答案正确。清空任务、切换任务和退出登录同步清空组件，旧事件由既有任务 generation 与游标隔离。

**技术栈：** TypeScript、Vite、原生 HTML/CSS、SSE、Playwright；沿用现有语义色和本地字体，不新增运行依赖。

## 设计选择

采用审查区内的有序步骤列表。与复杂关系图相比，它适合本期顺序计划、文本证据和窄屏；比只展示原始事件JSON更容易辨别当前步骤。用户可以展开节点查看必需工具、验收原因和来源。既有协作图保持独立，避免把主计划节点和子Agent节点混淆。

开发者在明亮办公环境中连续阅读代码与审批；使用柔白内容、浅青灰审查、浅绿当前状态，深色沿用石墨色。颜色只辅助文字，不单独传达状态。说明统一为“结构契约通过，结果正确性仍需核对”。

## 输入与输出

输入为既有本人 SSE 事件：`plan` 初始可信快照、`plan_replanned` 新修订快照、`plan_fallback` 原因及可选降级快照、`node_started`、`node_accepting`、`node_accepted` 和 Run 终态。以冻结运行器的最终事件字段为准，接入前逐项核对。

输出为可展开的节点列表和“已通过X/Y步”摘要。待执行、执行中、验收中、结构通过、阻断均有文字；任务终止时尚未通过的节点显示停止或待核对，不能仅凭 completed 事件把所有节点标为通过。无结构化计划的旧运行隐藏该区域，并在事件中说明兼容执行。

重规划展示已完成前缀和新后缀，保留服务端history中的有界旧节点与原因。复用工具来源展示“历史结果复用，非重新执行”，不声称新鲜观察。验收失败展示具体原因；成功显示结构契约通过，但始终不显示“语义验证成功”。

## 数据与交互边界

- 只接受有限非负整数revision、最多8个唯一文本节点ID、有限状态及有界文本；未知事件、旧修订节点事件和未知节点忽略。
- 所有不可信字段用textContent；节点目标、指令和证据中HTML不能执行。
- 节点详细区用原生details/summary，支持键盘；更新保留同节点的展开状态和焦点，不重建整个列表打断阅读。
- live区域只播报上下文完整的摘要，不把大工具正文或每个模型片段反复播报。
- 不显示内部模型请求、风险模型正文、reasoning或系统提示；已公开的本人节点目标与有界验收证据可查看。
- 节点ID、版本、摘要和证据字段均有展示上限，畸形事件不能产生无限DOM或横向溢出。
- 深浅主题、390px/768px/1440px、减少动画均验收；交互保持44px操作区和可见focus。
- 清空、登录退出、切换任务后不残留旧计划；事件连接重试不创建新Run、不重新执行工具。

## 分步实施与验收

- [x] **一：浏览器红例。** 通过真实本机HTTP创建两节点计划，要求首节点答复不结束任务，页面显示2节点；刷新后节点及验收来源不变。在旧界面应缺少计划区域或真实状态断言失败。
- [x] **二：最小组件。** 将事件状态与DOM更新集中到独立模块，app只负责分发和清空；不新增前端状态管理框架。典型调用为 `progress.accept(type, data)`、`progress.settle(run.status)`、`progress.clear()`。
- [x] **三：困难负例。** 验收失败和重规划、工具拒绝、预算失败、恶意文本、旧修订、未知节点、刷新及跨任务清空。失败任务不能显示“全部通过”；截图含真实中文状态而非伪造静态mock。
- [x] **四：构建及回归。** 执行 `npm.cmd run frontend:verify`，要求退出0；执行 `.venv/Scripts/python.exe scripts/run_ui_acceptance.py --module scripts.plan_browser_acceptance --module scripts.model_output_browser_acceptance --module scripts.file_changes_browser_acceptance`，要求所有模块完整退出0。
- [x] **五：简化与独立双审查。** 合并重复文本与状态映射，保持模块职责；规格通过后再质量审查，修复后复验，不用实施报告代替实测。
- [ ] **六：文档与提交。** README增加使用入口、截图导览更新，本批中文功能提交后按已有授权同步GitHub。0.2.9冻结安装包不覆盖，明确新展示仅源码。
