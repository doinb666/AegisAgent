# 站内通知使用指南

顶部铃铛显示本人未读数量。打开可查看任务完成、失败、等待审批和需要人工核对的提醒；点击一条通知标记已读并定位任务。审批依然要求核对工具名与完整参数后单独决定。

通知与来源事件同事务保存，事件ID是唯一通知ID。只记录任务标题摘要和状态，不复制回答、工具参数或敏感证据。通知不会向邮件、企业聊天或其他成员发送。同企业其他成员与管理员仍不能直接读取别人的私有通知。

## 读取与恢复

列表默认20项、最多50项，以事件ID稳定分页。未读计数30秒刷新，当前任务终态也触发刷新。点击刷新可立即读取；网络失败保留已有列表，避免重复创建任务。通知面板支持Escape关闭并恢复铃铛焦点。

点击通知只标记已读；任务若读取失败，可再次点击。退出账号会清空通知与定时刷新，旧响应不能写回新账号空间。只读成员可管理自己的已读状态，不会因此获得执行权限。

## 旧库启用

全新数据库自动启用，旧数据库新增通知表需显式迁移。先维护停写、预览，执行时提供新备份，再重启：

```powershell
python -m app.harness.notification_migration --data-dir data
python -m app.harness.notification_migration --data-dir data --apply --backup backups/before-notices.sqlite
python -m app.launcher --data-dir data
```

新版wheel启动器支持 `aegiscode --migrate-notifications`，EXE支持 `AegisCode.exe --migrate-notifications`。SQLite新备份不可覆盖已有文件；PostgreSQL先完成pg_dump。重复执行不新增通知，也不重置已读。历史事件没有事件时间列，补齐通知的created沿用任务创建时间，不将其称为实际完成时间。

## API与验收

| 路径（前缀 /api/v1） | 行为 |
|---|---|
| GET /notifications?limit=20&before=123 | 本人通知分页，跨用户游标404 |
| GET /notifications/unread | 本人未读数量，不读取工具证据 |
| POST /notifications/{id}/read | 幂等标记已读，重复调用保留首次时间 |
