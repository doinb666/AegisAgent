# 技能与记忆按需召回

源码与0.2.10安装包提供轻量目录投影，专项、独立双审查及全量回归通过；0.2.9保留旧召回实现。资产导入、审核、启用与退役方式保持一致，内核见[第35号记录](升级方案/35-Skill轻量投影与兼容性验收.md)，安装与公开下载见[第47号](升级方案/47-0.2.10安装与公开发布验收.md)。

## 怎样让技能容易找到

技能名称和description描述用途，tags标记领域；directory组织技能目录。examples写典型任务，boundaries写不适用条件，trigger_conditions说明使用前提。先在技能库检查内容和资源，再启用。草稿与退役技能不进入任务召回。

例如技能用于“检查Python异常处理”，description与tags应包含异常处理或Python等实际任务词，而不只写“万能助手”。正文写执行步骤；references等资源只在需要时用skill_read读取，不自动执行上传脚本。任务没有某个工具权限时，依赖该工具的技能会被排除，技能不能授予新的权限。

## 两阶段读取

第一阶段从数据库选择最多500项本人有效资产的id、类型、名称、版本以及8个元信息字段，不读取正文或资源体。按已有词法规则粗排最多32项，再按精确id与版本读取正文，重新核对所有者、租户、状态、类型和工具需求。

第二阶段校验技能文件与资源路径，根据正文前3000字符精排，最多返回8项；偏好、约束和画像保留原有加分。资源正文被剥离，只提供合法资源路径，需要时读取。两阶段间修订或退役的资产跳过，避免将新正文套入旧排名。已进入任务上下文的快照不会因以后退役而自动改写，后续召回采用最新状态。

这是一项读取优化，没有改为向量检索，也没有保证任意规模的技能全部参与排名。500项仍按名称与id取有界窗口；32项里无效或变更的候选不无界回填，所以可能不足8项。中文词法与英文词项依旧有边界，详细契约见[第34号](升级方案/34-Skill按需正文读取实施契约.md)。

## 环境与诊断

新增投影使用SQLite的JSON字段文本提取，需要SQLite 3.38.0及以上。检查实际Python运行时，而不只看Python版本：

```powershell
.venv/Scripts/python.exe -c "import sqlite3; print(sqlite3.sqlite_version)"
```

旧或未知SQLite版本返回503并说明升级或使用PostgreSQL，不发送不支持的查询。升级Python运行时前先备份数据；PostgreSQL是既有可选存储，需要按部署指南配置，不能通过切换配置替代数据迁移。

投影保留JSON字段文本，避免超大整数或科学计数浮点在数据库提取阶段丢失词项；缺失tools按既有空清单处理，显式null或非法工具类型拒绝，不放宽权限。资源路径异常、无效旧元信息和越权候选不注入。

暂无真实速度、Token或缓存收益结论；SQLite实测与PostgreSQL方言编译分别记录，不把编译通过称为真实数据库专项通过。
